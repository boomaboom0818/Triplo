# Local sustained-training operations

The reusable runner is operational tooling, not a declaration of playing strength.
Use a reviewed recipe and measured checkpoints; preserve the evidence gates and
label explicitly authorized exploratory extensions separately from promotion.

Example next bounded extension, only after the current 1,000-stage evidence review:

```sh
.venv/bin/python -m scripts.sustained_train \
  --output runs/bot/sustained-001 \
  --parents runs/bot/sampling-curve-001/candidate-a-1000.json runs/bot/sampling-curve-001/candidate-b-1000.json \
  --stages 1250 1500 \
  --validation runs/bot/campaign-001/validation-250.json \
  --seed 5400000 \
  --deadline 2026-11-14T17:31:00+00:00
```

Stages are total iteration counts. Output names use candidate-0/1 in the order of
`--parents`; the manifest records exact parent paths and hashes. The runner
preserves each parent's sampler, abstraction, seed, archive/population settings,
node cap and table cap. It adds only the next iteration target, 50-iteration
checkpoint cadence and one-hour invocation budget. Each child has a 3 GiB
address-space limit and reduced priority. Parents are never overwritten.

Each stage is evaluated over 1,000 shared independent deal blocks, against scripted
populations and the frozen validation checkpoint. Retained block samples support
paired stage-versus-parent and stage-versus-uniform comparisons. Outputs retain
hash/mode provenance; evaluation JSON is parsed and checked before atomic
publication. Resource stops halt explicitly; they do not certify convergence.
No cloud jobs or live OpenPoker actions are involved. Live-fallback results must
remain separately labeled and are not automatically generated by this runner.

Recovery after inspecting failure logs and checking actual processes:

- Repeat the exact command with `--resume`. Manifest and initial/per-stage parent
  hashes must match. Completed checkpoint/report work is skipped and validated.
- Partial training resumes its current checkpoint only for known time/interruption
  stops, with validated configuration and RNG state. OOM, table/node exhaustion,
  corrupt checkpoints and unknown failures require investigation before retry.
- Inspect `.pending` evaluation output after failed evaluation. It is diagnostic
  output, not a published report. Existing invalid final reports cause a stop;
  preserve and quarantine only after diagnosis before rerunning them.
- One supervisor lock and per-report locks prevent duplicate writers. Never
  bypass locks or run a second trainer against an already owned output path.

The deadline is checked before every child launch. A child still running at the
cutoff receives SIGTERM and up to 120 seconds for graceful completion/checkpointing;
if it cannot stop, it is killed and the prior complete checkpoint remains the
recovery source. No further stage launches after a deadline stop. Supervisor
SIGINT/SIGTERM uses the same child cleanup path. The overnight finalizer provides
an additional independent check at 17:31 UTC.

A completed run ends `completed_pending_evidence_review`. Review coverage by
street/active players, paired payoffs, tight-script regressions, variance and
memory/table growth before scheduling another extension. Development-set gains
must not be presented as final-test or competitive-strength evidence. The final
seed range 6,100,000 remains untouched.
